# DeepSeek Harness Chrome 侧边栏插件设计

日期：2026-10-30

## 目标与范围

在 Chrome 原生侧边栏中使用已经运行的本地 DeepSeek Harness，支持本地项目关联、项目会话、流式聊天和网页划词引用。通过 dsh 的插件安装机制分发宿主组件及配套 Chrome 扩展。

参考本机 ChatGPT 扩展 1.26.1020.11845 的侧边栏与上下文交互，独立实现代码和视觉资产。第一版不包含自动点击网页、表单操作、截图识别、书签或浏览历史采集。

## 交付结构与安装

对用户交付两个互相关联的组件：dsh 宿主插件与 Chrome 扩展。本机消息桥接随宿主插件提供，不要求用户单独安装第三个产品。技术上保持三个边界清晰的模块：

1. **dsh 宿主插件**：通过 bundle patch 加载进用户现有 desktop profile，调用该宿主公开服务处理项目、会话与消息。
2. **Chrome 扩展**：Manifest V3，包含原生侧栏、划词菜单、上下文草稿和聊天界面。
3. **本机消息桥接程序**：由 Chrome Native Messaging 启动，经本机 IPC 连接宿主插件；Chrome 的长连接消息端口承载请求、流事件与断开通知。

宿主插件提供每个运行实例的发现信息，桥接按本机用户和实例建立连接，不扫描全部端口，不使用固定的 50396 地址。不启动替代 dsh，不改变原有认证和公共 API 信任边界。

### 单入口安装，双向补齐

用户只需主动选择一个安装入口。安装流程负责检测另一端、准备或安装缺失的配套文件、完成当前用户的本机桥接注册、协商版本并验证连接；Chrome 和操作系统要求的安装确认由用户完成。不能将“准备好安装”显示成“已安装”。

- **从 dsh 开始**：安装宿主包后进入配套安装流程，部署桥接及 Native Messaging 清单，检测 Chrome 扩展；缺失时打开正式 Chrome Web Store 安装页并等待连接握手。正式上架前，开发包准备稳定 ID 的扩展目录并展示“加载已解压的扩展程序”指引，不能假称已自动加载。
- **从 Chrome 开始**：扩展首次运行检测 Native Messaging 宿主并握手；宿主存在而 dsh 插件缺失时，由宿主触发受限的配套插件安装流程；宿主也缺失时，显示并打开配套安装程序下载入口。用户运行安装程序后，程序检测已有 dsh，安装配套插件并注册桥接；不重复安装已存在的 dsh。扩展等待并重试连接，不要求用户自行寻找插件包和执行多套命令。
- **首次引导边界**：Chrome 扩展不能在 Native Messaging 宿主尚未安装时执行本机安装命令；缺失时只能引导用户运行配套安装程序。已安装 dsh 若没有可调用的安装协议，也不能凭空被浏览器远程调用。这个首次确认保留，后续配套步骤自动继续。
- **修复与更新**：任一端显示两端版本及连接状态，提供“安装配套组件”“修复连接”“更新配套组件”。已满足目标版本的操作直接成功，不重复安装、不形成互相唤起循环；不匹配时显示具体不兼容版本。
- **发布入口**：正式安装页、商店 ID、安装程序地址与预期版本来自包内发布清单。未配置或未发布时显示“开发版安装”，不生成不存在的商店链接，不从网页指令接收任意下载地址。

### 双向接口

采用版本化请求/响应信封，统一字段为 `protocolVersion`、`requestId`、`method`、`params`；响应携带原请求 ID、结果或结构化错误。安装类调用仅在用户触发配套安装或修复时执行，不能由网页选区、模型消息或普通内容脚本触发。

| 方法 | 发起方向 | 合同 |
| --- | --- | --- |
| `integration.status` | 任一已连通端 | 返回宿主、扩展与桥接的版本、能力及连接状态；不能连通的对端标记 unknown，不猜成未安装 |
| `integration.handshake` | 任一端 | 交换协议范围、组件版本、实例身份和能力，建立连接或返回不兼容原因 |
| `installation.ensureCompanion` | 任一端经安装协调器 | 接收目标组件和发布清单版本，幂等检查并开始受支持的安装流程；返回 ready、awaiting-user、installing 或 failed |
| `installation.openEntry` | 任一端 | 打开发布清单内允许的商店页、配套安装程序页或本地开发指引 |
| `installation.progress` | 安装协调器推送至已连接端 | 携带 operationId、阶段、用户待办和可恢复错误；断线后按 operationId 查询，不重复运行安装 |

对端尚未安装时，上述接口并非可直接调用的通道；本地引导界面先完成首次安装，再通过真实握手接续。自定义 URL 协议若后续使用，仅用于唤起已注册的安装协调器，不携带 shell 命令、凭据或任意路径，不作为第一版必须存在的前提。

本机消息宿主的注册仅针对当前 Windows 用户和明确的扩展 ID。提供独立可测试的安装协调器，不依赖可能被包管理器拦截的隐式 postinstall 脚本。卸载不删除项目文件或会话历史，不自动删除另一端；保留其修复、重新安装和查看历史的入口。

## 隐藏默认项目

- 第一次启用宿主插件时，在 dsh 用户目录下创建独立工作目录：`$DSH_HOME/chrome/default-project`，缺省为 `C:\Users\yifan\.dsh\chrome\default-project`。
- 由插件持久化稳定的默认项目 ID 和目录，后续加载复用，不因侧栏重开、断线或 dsh 重启重复创建。
- 这是插件管理的私有默认项目，不注册进普通 `workspaceRegistry` 项目列表，因此不在 dsh 的普通项目列表中创建一条“隐藏”名称的可见项目。
- 侧栏项目选择器显示“默认”，普通项目列表不重复列出其物理目录。这里的“隐藏”针对项目目录和普通项目列表，不代表删除或隐藏对话历史。
- 默认会话的实际工作目录就是上述目录，禁止回退到用户主目录、浏览器目录或随机代码项目。
- 用户没有选择项目时使用默认项目；显式选择的项目在本机持久化，用户可随时切回“默认”。
- 一个已创建会话的所属目录不可因为切换项目而改变。切换项目切换该项目的会话范围；草稿及待发送引用按项目保留，不能自动混入另一个项目。
- 目录被删除时，在下一次创建默认会话前重建；若路径变成文件或权限不足，则显示明确错误并保留草稿。

## 侧栏交互

顶部包含连接状态、项目选择、新建对话和会话列表入口。主体展示当前会话的用户消息、模型回答和流式状态。底部是引用卡片、输入框、发送和停止按钮。

普通项目从当前 dsh 宿主读取，显示项目标题和目录以区别同名项目。新建会话使用所选项目的真实工作目录；恢复会话时以 dsh 会话记录为准校验归属。默认项目在插件自己的目录范围内管理会话。

宿主配置、模型凭据和工具执行沿用 dsh。需要用户授权或回答的问题，必须提供可操作提示或明确引导到 dsh 当前会话；不能让侧栏一直显示无解释的“思考中”。

## 划词上下文

第一版包含两个入口：

1. 在网页选中文字后，右键“添加到 DeepSeek 对话”，将文字添加到当前项目的当前草稿，尽可能打开侧栏。
2. 在已打开侧栏中点击“添加选中文字”，读取当前标签页的选区。

引用卡片包含原文、网页标题、来源 URL 和捕获时间，允许预览全文、删除及连续添加多段。只处理用户明确添加的选区，不自动采集整页。默认项目也完整支持此流程。

侧栏尚未选择会话时先保存引用草稿，发送时为当前项目创建会话。侧栏已关闭或首次启动时，待处理引用先持久化，再打开侧栏，避免界面初始化造成丢失。相同来源与相同文本的重复添加给出提示，允许用户明确保留重复内容。

添加引用不立即调用模型；点击发送后，将问题及引用一起作为用户消息持久化并交给 dsh。引用采用清楚的文本边界和来源标注，属于不可信网页资料，不能被当成宿主指令。发送成功后清空已确认提交的草稿；失败则保留。

限制页、浏览器内部页面、无选区和超长选区分别给出可理解提示。超长选区不静默截断：显示长度与限制，由用户缩短后再添加。具体上限由插件配置并在界面显示。

## 消息与连接

扩展 service worker 管理 Native Messaging 连接和事件转发，持久化草稿、待处理选区及请求状态。侧栏只维护界面订阅，不依赖其始终打开。

协议包含版本、请求 ID、操作名、参数、响应和事件；宿主验证参数并使用公开服务，而非直接编辑 dsh 会话存储文件。创建会话、发送消息、停止生成、查询会话及事件订阅属于不同操作。

每条发送请求具有稳定的客户端消息 ID。宿主为同一 ID 去重并返回确认；连接中断后先查询状态，绝不直接重复执行。多侧栏同时查看同一会话时，以宿主权威状态恢复历史与流事件。

本机 IPC 使用按用户隔离的实例发现及配对凭据，限制消息大小并校验消息形状。安装包和浏览器存储不包含 DeepSeek API Key。版本不兼容时明确报错，不尝试旧协议猜测回退。

## 实施前必须完成的兼容性验证

以安装版 `0.2.1-rc.3` 的模块和 CLI 为准，验证：

- bundle 插件安装、加载和卸载入口；
- 宿主公开服务的会话创建、发送、取消与历史订阅；
- 已注册项目的枚举与目录校验；
- 私有默认目录创建会话时不会被主动注册成普通项目；
- Native Messaging 的扩展 ID、进程启动和本机 IPC 生命周期。

如公开扩展点不足，停止在兼容性失败处并报告具体限制；不得通过改写已安装的 `app.asar` 或直接修改已有会话数据库绕过。

## 验收与测试

自动验证覆盖默认项目幂等创建、无项目选择回退、切换项目草稿隔离、选区入队与去重、消息确认与断线不重发、协议拒绝和流事件恢复。

浏览器人工联调覆盖：Chrome 加载扩展；dsh 加载宿主插件；连接当前运行实例；在默认项目发送并停止回答；选择真实项目新建和恢复会话；选区右键添加；多段引用预览删除；关闭侧栏后添加；重开与重启后的恢复；受限页面提示；权限请求与错误反馈。

安装验收分别从“仅有 dsh”“仅有 Chrome 扩展”“两端均已安装”“一端版本不兼容”“安装中断后重试”出发。检查双向补齐、首次用户确认、操作幂等、连接自动恢复，以及开发版和正式版安装文案的真实性。无已发布商店包或配套安装程序时，正式分发路径标为未验证，不以本地加载结果代替。

只有真实宿主和浏览器联调通过后，才能声称“已连接现有 dsh”“可以通过 dsh 安装”或“划词功能可用”。模拟测试通过需单独标注，不能替代实际联调。
